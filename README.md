# LP Service V2

サービスLP（ランディングページ）専用のWordPressテーマです。通常の投稿・固定ページは使わず、独立した1ページ完結のLPを複数管理するための構成になっています。

## 特長

- カスタム投稿タイプで構成します。
  - `service`（管理画面表示名「LP管理」）: LP本体。1件が1つのLPに対応し、URLは `/{スラッグ}/`、絞り込みページは `/{スラッグ}/search/` です。
  - `product`（「商品管理」）: LPに紐づく商品・買取業者など。1つのLPに複数登録できます。
  - `operator_info`（「運営者情報」）: LPのフッターからリンクする運営者情報ページです。
- LPごとにデザインテンプレート（スタンダード / シンプル / シンプル・ポップ / シンプル・トラスト）を選べます。ポップ・トラストはスマホ専用の幅（最大430px）です。
- Gutenbergのカスタムブロック（名前空間 `lp-service`）でLP本文と商品情報を組み立てます。比較テーブル、ランキング、絞り込みフォーム、CTA、ポイント、自由入力などがあります。
- 商品はLPごとに設定したセレクト2種・チェックボックス4種で絞り込み表示できます。
- 管理画面に操作ガイド（オンボーディングツアー）があります。

注意: サイト直下の1階層URLはすべて `service` 投稿として解決されるため、通常のWordPress固定ページとは共存できません（LP専用サイト向けのテーマです）。

## 動作要件

- WordPress: `style.css` のヘッダーでは 6.0 以上、PHP 7.4 以上と宣言しています。ただしブロックは `apiVersion: 3` で作られているため、実際にはより新しいWordPress（6.3 以上が目安）が必要な可能性があります（要確認）。
- ビルド済みの `build/` が同梱されたzip（Releasesで配布）を使う場合、サーバーにNode.jsは不要です。
- 開発する場合: Node.js と npm が必要です（`@wordpress/scripts` 30 系を使用。対応するNodeのバージョンは要確認）。

## 初回インストール

1. このリポジトリの Releases ページから最新版の `lp-service-v2.zip` をダウンロードします。
2. WordPress管理画面で「外観 > テーマ > 新規追加 > テーマのアップロード」を開き、zipをアップロードして有効化します。

GitHubが自動生成する「Source code (zip)」は使わないでください。フォルダ名が `lp-service-v2-1.4.0` のようになり、また `build/` を含まないためブロックが動きません。必ずReleasesに添付された `lp-service-v2.zip` を使ってください。

リポジトリURL: https://github.com/inflow834/lp-service-v2

最初に自動更新に対応するバージョンは 1.4.0 です。それ以前のバージョンからは自動更新されないため、各サイトに手動で 1.4.0 以降を入れてください。

## 更新のしくみ（サイト管理者向け）

- テーマは GitHub Releases を定期的に確認し、新しいバージョンがあるとWordPress標準の更新通知として表示されます。「外観 > テーマ」または「ダッシュボード > 更新」から更新できます。
- WordPressの更新確認は1日2回程度のため、公開から反映まで最大12時間ほどかかります。すぐ確認したい場合は「ダッシュボード > 更新」の「再確認」を押します。
- 「外観 > テーマ」でテーマを選び、自動更新を有効にすると、WordPressが自動で更新します（サイトごとに設定）。
- 更新してもLP・商品・運営者情報などのデータ（データベース内のコンテンツ）は変わりません。一方、テーマのファイルを直接編集していた場合、その変更は更新時に上書きされて失われます。カスタマイズは子テーマまたは別のプラグインで行ってください。

メンテナー向けのリリース手順は [RELEASING.md](RELEASING.md) を参照してください。

## 開発

```
npm install        # 依存パッケージのインストール
npm run build      # ブロックを build/ にビルド
npm run start      # ウォッチモード（ファイル変更で自動ビルド）
```

- ブロックのソースは `src/blocks/*`（`block.json` / `edit.js` / `save.js` / `render.php` / `*.scss`）、共有コードは `src/shared/` にあります。
- `build/` はビルドで生成されるファイルで、リポジトリにはコミットしません（リリース時にGitHub Actionsがビルドします）。ローカルでテーマを動かすには先に `npm run build` が必要です。
- PHPは `functions.php` から `inc/*` を読み込む構成です。テンプレートは `single-service.php`、`template-parts/` などにあります。
- バージョンは `style.css` の `Version:` を唯一の基準とします。ブロックのCSS/JSのキャッシュ更新にも使われるため、変更を配布するときは必ず上げてください。
